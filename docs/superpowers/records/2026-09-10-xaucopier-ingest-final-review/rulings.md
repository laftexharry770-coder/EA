# Controller rulings for the Plan 2 final fix wave (extracted from the ledger)
Where a ruling differs from a reviewer's proposed fix, the RULING wins.

Ruling (C1 + three seed MUST-FIX + minors 114/144): persist a per-channel seed cutoff (channel_state.seed_cutoff_utc, written insert-if-absent at the FIRST attempt, before any seed RPC, as min(local, Telegram server time) truncated to whole seconds). Every seed uses the stored cutoff, never the process start. The seed re-runs every round while the channel is unseeded; a successful seed persists the pointer (0 included, via an explicit seeded marker) and clears the cutoff. Using a stored cutoff older than 10 minutes logs a WARNING naming its age. Cost if wrong: an unseeded channel costs up to 2 RPCs per round until it seeds.

Ruling (M12, same machinery): `channels on N` for a channel that already has a pointer writes seed_cutoff_utc = now, so the next watch re-seeds it there — OFF means "posts made while it was off are ignored", not "paused". Posts after switching back on are still caught up. Cost if wrong: posts made while OFF are never recorded.

Ruling (C2): a relay copy's edit is reconciled against the signal it duplicated (recorded at ingest in messages.relay_of_signal_id), exactly like an edit of the holder, with the alert naming both messages. A deletion of a CROSS-channel copy while the signal is unexecuted VOIDS it (doing nothing is the safe side; one source withdrew the call); executed -> CRITICAL flag. A deletion of a SAME-channel copy (a double post) only warns. Cost if wrong: a relay admin's tidy-up voids an unexecuted signal — loudly, and under Plan 3 the unexecuted window is seconds.

Ruling (C4/C6): same-channel matches of a signal that is VOIDED/INVALID/withdrawn AND unexecuted are NOT duplicates — the repost becomes a new signal. Cross-channel matches of such a signal stay suppressed but raise a CRITICAL alert. When a holder is withdrawn while unexecuted and a same-channel repost (posted after it, not deleted) stands, the repost is promoted to the signal (signals row + fan-out) with a WARNING. Every relay_duplicate outcome is logged and counted. Cost if wrong: a poster's deliberate double-post-then-delete-one keeps trading once, which is correct.

Ruling (C5): REVISES the Task 10 "edits never create" ruling on new evidence (the healthy path is the one that misses the trade). A message stored as parse_failed/skip that an edit turns into a valid signal within 120 s of posted_at (policy.edit_grace_seconds) becomes a NEW signal, fanned out, with a WARNING EDIT_COMPLETED_SIGNAL. Beyond the grace, keep the ruling and raise EDIT_CREATED_SIGNAL to CRITICAL (it asks the user to act by hand). Cost if wrong: a signal completed by a quick edit trades, which the blackout path already does.

Ruling (C10): record sender metadata at ingest (post flag, sender peer kind + id, forwarded-from channel id); the pickers show "channel" or "group" and require a plain-words confirmation for a group; watch logs each source's kind at start. No sender filter yet — the real COMMUNITY's kind is unknown (VERIFY-ON-FIRST-LOGIN), and a wrong filter would drop every signal silently. PLAN3 obligation #34: a sender filter for group sources before any execution.

Ruling (F07): the router classifies entry-shaped text (a side word BUY/SELL plus an SL value, with a gold alias or a TP value) that failed the channel parser as parse_failed, never a follow-up — it feeds the counter. Parsing/followups.py and channel_mmh.py are NOT modified (Plan 1 core, Plan 1b builds on it). Ruling (F08): a follow-up replying to a stored signal message resolves its target at ingest — the holder's signal, or relay_of_signal_id for a relay copy — recorded as target_signal_id with resolution_path 'reply' / 'relay-reply'. A follow-up is a relay duplicate (stored, no outbox row, logged and counted) when an existing follow-up with the same op and normalised content hash targets the same signal within the relay window, or when it carries the same (fwd_from channel, channel_post) as a stored follow-up. Non-reply follow-ups are NOT text-deduplicated across channels (two genuine "close half" calls must both act). Plan 3 obligation: reply resolution uses the ingest-time target. Cost if wrong: a relayed non-reply follow-up is queued twice; Plan 3 resolves each per channel (spec 8.1 rule 3), so the relay copy finds no signal on its own channel and alerts.

Ruling (F09): record fwd_from channel id, channel_post and date at ingest. A (fwd channel, channel_post) pair matching an already-stored message (or that message's own (channel, id)) is an exact relay duplicate regardless of lag, for signals and follow-ups. posted_at stays the copy's own date (spec G6 unchanged); the age-gate basis for forwards is a Plan 3 decision after measuring COMMUNITY's forward lag (VERIFY-ON-FIRST-LOGIN). Cost if wrong: none for dedup; the age-gate question is surfaced, not decided.

Plan 3 obligation: OFF channels with live legs. The M12 re-seed stands. Cost if wrong: a trade opened from a channel later switched off loses its channel follow-ups (its SL/TP and the Plan 1b trailing stop still manage it).
